These are six questions I'd like the AI4IE working group to discuss. They're my list, not
the group's agenda. If you have evidence, disagree with the framing, or have another question,
[send your view](/contribute/?type=other#send-a-contribution) or raise it in the
[AI4IE Discord](https://discord.gg/zhHAZakXHX).

## How should an LCA assistant be validated?

Benchmarks show that large language models (LLMs) make frequent errors on LCA tasks: experts found errors in 37.2% of answers in one test <Cite id="donaldsonExpertGroundedBenchmark2025" />. See [more benchmarks](/best-practices/#how-reliable-is-ai-today). But there is no agreed passing standard for an assistant or agent (an LLM that calls tools and edits files over several steps) that suggests processes, writes Brightway or openLCA code, or interprets results.

Useful evidence or proposals:

- Worked validation protocols run on real Brightway or openLCA workflows, not isolated Q&A prompts.
- Criteria separating minor drafting errors from disqualifying methodological mistakes.
- Comparisons between single-prompt use, retrieval-augmented setups (where a model searches documents before answering), and tool-using agents on the same IE tasks.

## How should papers disclose AI-assisted inventory and modelling work?

Journal policies ask authors to declare AI use. The policies I have read don't separate spell-checking from writing analysis code or mapping life cycle inventory (LCI) flows. Reviewers need enough detail in the methods or supplementary material to judge what was checked by hand and where model errors could enter the results.

Useful evidence or proposals:

- A tiered disclosure scheme that separates prose editing, code generation, and AI-assisted LCI mapping or gap-filling.
- Concrete methods paragraphs and supplementary logs from published or submitted IE studies.
- Practical additions to the existing [verification checklists](/best-practices/verify/) that reviewers can apply in under ten minutes.

## Who maintains golden questions, and how are they kept out of training data?

I collect candidate golden questions: IE tasks with known answers or scoring rubrics. I don't publish them as a fixed benchmark. Questions in a public repository can end up in future models' training data, and then a model can score well by memory. Keeping a test set private avoids that, but someone then has to curate, update and run it fairly.

Useful evidence or proposals:

- Governance models for a rotating or institutional curator group within ISIE or the AI4IE working group.
- A workable split between public candidate examples and a private, held-out evaluation set.
- A renewal cadence so test tasks keep pace with new database versions and impact methods.

## Should AI-assisted IE studies report their own compute footprint?

Do the energy and emissions of running AI tools matter next to the study's own footprint? Fine-tuning a model or running thousands of agent loops uses far more than a few prompts, and there is no shared reporting threshold or log format.

Useful evidence or proposals:

- Order-of-magnitude bounds showing when the energy for training or querying a model is large enough to report in a typical IE study.
- A minimal log researchers can actually keep (model name, token counts, hardware, or measured energy).
- Measurement tools that work for both hosted APIs and local setups listed under [local AI & hardware](/tools/local-ai/).

## What shared evaluation datasets can the community publish without licensing blocks?

Background databases such as ecoinvent are proprietary, so researchers can't publish evaluation tasks that bundle real process data. Tools then get tested on data that nobody else can inspect or rerun.

Useful evidence or proposals:

- Open-licensed inventories or public datasets from [datasets & models](/tools/data-and-models/) that support realistic LCI and MFA tests.
- Synthetic or anonymised inventories that keep real edge cases such as multi-output allocation and unit conversions.
- Licence-compatible task templates that reference database identifiers without redistributing restricted tables.

## Where should human review remain mandatory in AI-assisted IE pipelines?

Automated checks catch syntax errors, broken unit conversions and mass-balance violations, so parts of a pipeline can run on tests alone. Methodological choices such as system boundaries, allocation rules and life cycle impact assessment (LCIA) characterisation factors change a study's conclusions directly, and a script alone can't check them.

Useful evidence or proposals:

- A concrete split between steps verifiable by automated checks and judgements requiring a named human sign-off.
- Documented failure cases where an AI tool silently changed a boundary, default parameter, or allocation choice.
- Lightweight review habits that fit a PhD or consultancy workflow, alongside relevant studies in the [reading list](/literature/).
