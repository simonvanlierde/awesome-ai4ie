## AI as a research method

- **Start with a baseline.** Compare your model with a simple one, such as linear
  regression. If the gain is small, explain why you need the more complex model.
- **Isolate the test set first.** Normalization, gap-filling and feature selection
  can leak information from the test set. For time-ordered data, split by time.
  Use the [ML reproducibility checklist](/best-practices/checklists/#machine-learning-reproducibility)
  or [check an existing pipeline for leakage](/best-practices/prompts-and-skills/#data-leakage-self-check).
- **Test where you plan to use the model.** A model trained to estimate building
  age from Toronto street-view photos was less accurate in five other Canadian
  cities. Report where you validated the model.
  [Building-age study](https://doi.org/10.1111/jiec.13591)
- **Compare with independent data.** One satellite map of building stocks agreed
  with most local studies, with large differences in some places. Report the
  discrepancy and explain how you estimate uncertainty.
  [Building-stock study](https://doi.org/10.1111/jiec.13585)
- **Check extracted values against the document.** In the
  [inventory studies](/applications-map/lca/), researchers use
  language models to extract values from documents and check them by hand.
  [Try the extraction prompt](/best-practices/prompts-and-skills/#extract-without-inventing).
  If you use synthetic data, describe how you generated it in the methods.
- **Report the pipeline in order.** State when you split, normalized and trained.
  Pin versions and seeds, record the environment, and explain any restrictions on
  sharing data or code.

## AI as an assistant

- **Give specific instructions.** Include the schema, units or method constraints
  the assistant needs. Check your data policy before sharing any material.
- **Review small changes.** Read the diff, run tests, and check numerical work on a
  case with a known answer. [AI-assisted coding checklist](/best-practices/checklists/#ai-assisted-coding)
- **Get a second review.** Open a fresh session and use the
  [code review prompt](/best-practices/prompts-and-skills/#adversarial-review-of-ai-written-code).
- **Verify claims and citations.** Open the primary source and check what it supports.
  [Source-checking prompt](/best-practices/prompts-and-skills/#verify-a-claim-before-citing-it)
- **Save instructions you reuse.** Put the workflow in a
  [skill file](/best-practices/prompts-and-skills/#agent-skill-files).

For more examples, see the [Prompt Engineering Guide](https://www.promptingguide.ai).

## Pitfalls

- **Invented references.** GPT-3.5 fabricated 55% and GPT-4 fabricated 18% of the
  references they produced in one study ([Walters & Wilder, 2023](https://doi.org/10.1038/s41598-023-41032-5)).
  In a benchmark on LCA questions, rates reached 40% for some models
  ([Donaldson et al., 2025](https://doi.org/10.48550/arXiv.2510.19886)).
  Open each reference before citing it.
- **Wrong numbers.** Trace each number you plan to publish to a primary source or
  recalculate it.
- **Confidential data.** A hosted service receives what you send and may retain it.
  Check your data-management plan and institutional policy before sharing anything.
  [Local AI options](/tools/local-ai/)
