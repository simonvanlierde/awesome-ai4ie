An **eval** is a fixed set of questions with known answers, run against one AI step (for example, a prompt that pulls a value out of a paper) and scored by a script. Run it before the step goes into your workflow, and again when the model, prompt, or data change.

## Score an AI step before you trust it

1. **Collect gold questions from real use.** Write the gold answer (the known correct one), or a check the answer must pass, next to each question.
2. **Add questions that differ from your examples.** Include reworded questions and off-topic ones the step must refuse. A set that looks like the prompt's examples tests copying, not understanding. Have a model you are not testing write the rewordings, and check by hand that each can be read only one way.
3. **Score with code.** Have a script compare each answer with the gold answer. Do not judge answers by reading them.
4. **Report correct out of _n_ for each kind of question, with a range, not just a score.** Use a Wilson 95% confidence interval: the range the true rate likely lies in. Add the model, its version, and the date. At small _n_ the usual error bar, from the normal approximation, is too narrow. Bowyer et al. ([arXiv:2503.01747](https://arxiv.org/abs/2503.01747)) found that only Wilson and Bayesian intervals keep their stated coverage there: a 95% interval holds the true rate 95% of the time. Miller ([arXiv:2411.00640](https://arxiv.org/abs/2411.00640)) gives the formulas for treating an eval as an experiment.
5. **Compare two models item by item, not by their totals.** Count the items that only model A got right and the items that only model B got right. Run an exact McNemar test, a paired test, on those two counts. Plan for about 60 items per kind. That gives an 80% chance (80% power) to detect a 20-point gap, such as 75% vs 55%, with exact McNemar at the 5% significance level. You need about 40 if the weaker model's misses include all the stronger one's, and about 100 if the two miss items independently. Kotawala ([arXiv:2605.30315](https://arxiv.org/abs/2605.30315)) found 11 of 40 pairwise comparisons on the Open LLM Leaderboard v1 unresolved at a 5% level and 80% power.
6. **Run each item more than once.** Temperature 0, the setting for the least random output, does not guarantee the same answer each run. For model graders (models that score other answers), Tamba ([arXiv:2606.26185](https://arxiv.org/abs/2606.26185)) found it "necessary and not sufficient", and some providers now reject the setting. Report how often an item's answer changes between runs.
7. **Keep the eval outside the agent's write access,** like a [golden test](/best-practices/agentic-harnesses/#2-protect-the-test). Keep a held-out set of questions, ones you never tuned the prompt on, outside the public repository. Run it only on a prompt you have stopped changing.

The studies cited in these steps are arXiv preprints.

### Worked example

The [RaMa-Scene explorer Ask eval](https://github.com/simonvanlierde/ramascene-explorer/tree/main/evals/ask) scores how well a model turns a question into a scenario (a what-if change to EXIOBASE products, regions or industries) for an EXIOBASE footprint engine. The gold set has four kinds: the labels of published scenarios, reworded questions, view questions, and off-topic questions that must get no action.

In its 2026-11-19 run (vLLM, 4-bit weights, temperature 0), Qwen3.8-27B answered 151 of 153 label questions correctly and Gemma-4-26B-A4B 135. Compared item by item, 16 labels went to Qwen and none to Gemma, so the exact McNemar p is about 0.00003: on labels, Qwen is better. But 15 of Gemma's 18 misses are one mistake repeated: on the electrical-machinery scenarios it named the industry where the product was asked for. Related items like these are not independent evidence, so count them as one finding, and fix the prompt or the gold before you rank models on them. The reworded questions show the opposite problem. Qwen got 6 of 8 (Wilson 95% interval 0.41 to 0.93) and Gemma 3 of 8 (0.14 to 0.69). All 3 differing items went to Qwen, and the exact McNemar p is still 0.25. Eight items cannot rank the two models, and most misses are readings the question allows. The eval is being extended along the steps above.

## Benchmarks for agents and models on research tasks

A benchmark score tells you how a model did on someone else's tasks. Use it to choose what to test, then run your own eval.

<p class="table-title"><b>Table 3.2</b> Benchmarks that test agents and language models on research, coding and LCA tasks</p>

| Benchmark | What it tests | Headline result |
|---|---|---|
| [CORE-Bench](https://arxiv.org/abs/2409.11363) | Agents reproduce published results from the paper's own code and data: 270 tasks from 90 papers in computer science, social science, and medicine | The best agent scored 21% on the hardest level |
| [ScienceAgentBench](https://arxiv.org/abs/2410.05080) | Agents write code for data-driven discovery: 102 tasks from 44 peer-reviewed papers in four disciplines | The best agent solved 32.4% of tasks alone, 34.3% with expert knowledge |
| [ImpossibleBench](https://arxiv.org/abs/2510.20270) | Coding tasks whose tests contradict the specification, so any pass is a shortcut | GPT-5 passed 54% of the Conflicting-SWEbench tasks |
| [Expert-grounded LCA benchmark](https://arxiv.org/abs/2510.19886) | 11 general-purpose models on 22 LCA tasks, reviewed by 17 LCA practitioners | Experts found inaccurate or misleading information in 37% of responses; some models hallucinated up to 40% of citations |
| [PCFBench](https://arxiv.org/abs/2608.27716) | 614 expert-labelled items across six product carbon footprint tasks, eight frontier models | The strongest models are within 2 times of declared totals on 77% of products, 37-58% when the footprint is built step by step, with only 45-75% of those obeying mass conservation |

<p class="table-src">Source: the abstract of each paper, except the ImpossibleBench rate (Section 4 of that paper).</p>

Scores date quickly as models change. Check the paper's date and the models it tested before you quote a number.
